# Повторная проверка требований ЛР3

Проверка выполнена 25 ноября 2026 года по исходному `LR3_2025.pdf` (4 страницы).
SHA-256 PDF: `181a53321d2d44e727ab52b23a451a99758e11dec8d8267fb312e3781e329f4d`.
Содержимое всех страниц повторно прочитано, включая две сноски на странице 3.
Проверялся проект из GitHub, исходная точка — коммит `4c18e43`.

PDF требует **C++ и один язык из Go/Rust**. Выбран Go: Rust дополнительно не нужен.
Это две самостоятельные реализации контейнеров, а не вызов C++ из Go или наоборот.
Основные требования находятся на странице 3; страницы 1–2 содержат вопросы к защите,
страница 4 — литературу. Отдельной таблицы числовых вариантов в PDF нет.

## Все структуры реализованы на обоих языках

| Структура | C++ | Go | Основные операции |
|---|---|---|---|
| Массив | [array.h](../str/array.h), [array.cpp](../str/array.cpp) | [array.go](../golang/ds/array.go) | добавление, вставка, индексы, изменение, удаление, очистка, размер и ёмкость |
| Односвязный список | [one_linked_list.cpp](../str/one_linked_list.cpp) | [one_linked_list.go](../golang/ds/one_linked_list.go) | вставка/удаление с обоих концов и до/после значения, поиск, прямой/обратный обход |
| Двусвязный список | [linked_list.cpp](../str/linked_list.cpp) | [linked_list.go](../golang/ds/linked_list.go) | те же операции, две ссылки в каждом узле |
| Стек | [stack.cpp](../str/stack.cpp) | [stack_queue.go](../golang/ds/stack_queue.go) | push/pop/top, LIFO, размер, очистка |
| Очередь | [queue.cpp](../str/queue.cpp) | [stack_queue.go](../golang/ds/stack_queue.go) | push/pop/front, FIFO, размер, очистка |
| Хеш-таблица | [open_hash.cpp](../str/open_hash.cpp) | [hash.go](../golang/ds/hash.go) | insert/erase/find/contains, рост, метки удаления, линейное и двойное пробирование |
| Полное двоичное дерево | [tree.cpp](../str/tree.cpp) | [tree.go](../golang/ds/tree.go) | вставка по уровням, поиск, полнота, высота, обход, структура, очистка |

Во всех контейнерах проверено независимое копирование: конструкторы/операторы
копирования C++ и методы `Clone` Go. Состояние закрыто (`private` C++; поля и узлы
со строчной буквы в пакете Go). Для времени жизни C++ использует деструкторы, Go —
сборщик мусора; это различие языков, а не отсутствие второй реализации.
Имена `size()/Len()`, `read()/String()` различаются, смысл операций сохраняется.

Дерево — вариант 3 личной ЛР1, Complete Binary Tree: повторы сохраняются,
вставка BFS слева направо. Вариант не заменён AVL-деревом примера.
Хеширование — вариант 5 личной ЛР2: DJB2/FNV-1a, два способа пробирования.
PDF предписывает взять вариант дерева из ЛР1, а не назначает каждому AVL.

Сноска PDF допускает для C++ только бинарную сериализацию при трудоёмкости
текстового формата. Здесь реализованы оба формата на каждом языке, то есть
послабление не использовано. Бинарные файлы совместимы между реализациями.

## Фактические проверки

- C++ заново собран из текущего проекта: Google Test — **132 теста**, Boost.Test —
  **51 случай / 12283 проверки**, Catch2 — **18 случаев / 12283 проверки**.
- Покрытие строк библиотеки C++: Google Test **1087/1090 = 99,72%**;
  Boost.Test и Catch2 **1084/1090 = 99,45%**.
- Go: библиотека **34 тестовые функции и 61 подтест**, CLI **1 тест и 8 подтестов**.
  Библиотека — **774/780 = 99,23%** операторов, CLI — **74/87 = 85,06%**,
  весь Go-проект — **848/867 = 97,81%**. Порог проверяется по каждому Go-файлу.
- Дополнительное сравнение публичных операций: **9440 шагов**, после каждого
  сравнивались результат, статус ошибки и содержимое контейнера. C++ и Go
  независимо сопоставлены с эталоном Python: массивом/списком/множеством и
  моделью полного дерева. Unicode, пустые строки, пробелы, кавычки, NUL,
  повторные значения, ошибочные индексы и отсутствие соседей включены.
- Проверка сериализации и CLI: **1450 запусков процессов**, оба языка и направления,
  оба формата, все структуры и оба режима хеширования, повреждённые файлы.
- `make verify` завершился успешно. Полный журнал —
  [reports/verify.txt](../reports/verify.txt); отдельное сравнение операций —
  [reports/semantic_parity.txt](../reports/semantic_parity.txt).
- Бенчмарки C++ находятся в `reports/cpp_benchmarks.*`, Go — в
  `reports/go/bench.txt`; новые три семейства дополнительно сохранены отдельным
  журналом `reports/go/bench_additional.txt`. C++: 32 размера/сценария × 3 повтора;
  Go: 36 × 3. Наборы размеров частично различаются; отсутствующие измерения
  отмечены прочерком. Время зависит от среды и подготовки данных.

Счётчики тестов, подтестов и отдельных проверок — разные величины. Метрики C++
измеряют строки `str/`, Go — операторы библиотеки и CLI. Они не выдаются за одну
и ту же метрику. Покрытие не доказывает отсутствие ошибок.

## Исправления по результатам аудита

1. На Go добавлены `BenchmarkArrayInsertFront`, `BenchmarkOneLinkedPopBack`,
   `BenchmarkLinkedPopBack`. Теперь все 13 семейств C++ имеют соответствие в Go.
2. Исправлено обозначение режима Go-хеш-таблицы в обзорном UML: `linear bool`,
   а не `ProbeMode` из C++-версии. Обновлены DOCX/PDF и SVG.
3. Исправлен путь к Go CLI в Makefile при абсолютном значении `BUILD`.
   Полный `make verify` повторно выполнен с отдельной папкой сборки.
4. Добавлен воспроизводимый `make parity`, входящий в `make verify`:
   [semantic_parity.py](../scripts/semantic_parity.py), тестовые адаптеры
   [C++](../tests/parity/cpp_driver.cpp) и [Go](../tests/parity/go_driver.go).
   Адаптеры вызывают реальные методы контейнеров и не входят в знаменатель покрытия.

Проверено на macOS arm64, Apple Clang 17.0.0, Go 1.26.2. Windows и Linux отдельно
не запускались. Устную защиту и требования сверх исходного PDF проверяет преподаватель.
