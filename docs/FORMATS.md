# Сериализация и десериализация

Оба формата реализованы для каждой структуры в C++ и Go. CLI обрабатывает
одну структуру в одном файле и отвергает лишний хвост. Библиотечные методы
читают одну запись из потока; это позволяет при необходимости последовательно
записывать несколько записей. Файлы демонстрации содержат UTF-8.

## Бинарный формат

| Поле | Размер | Содержание |
|---|---:|---|
| Tag | 4 байта | Тип записи |
| Count | 8 байт | uint64 little-endian, число элементов |
| Элементы | переменный | Строки или числа дерева |

Строка: 8 байт uint64 little-endian длины в **байтах**, затем столько байтов.
Нулевые байты, переводы строк, кавычки и UTF-8 не меняются.
Число дерева: int32 little-endian, отрицательные значения представлены дополнительным кодом.
Структуры C++ в память целиком не выгружаются: указатели и служебные поля не сохраняются.

| Тип | Tag | Заголовок текста |
|---|---|---|
| Array | ARRY | Array |
| OneLinked | LIN1 | OneLinkedList |
| Linked | LIN2 | LinkedList |
| Stack | STAK | Stack |
| Queue | QUEU | Queue |
| OpenHash (double) | HOPN | OpenHash |
| OpenHash (linear) | HLNR | LinearHash |
| Tree (Complete) | CTRE | CompleteTree |

Если поменяете тип или режим хеширования при загрузке, несовпадающий тег вызывает ошибку.

## Текстовый формат

Первая строка: `ИмяТипа количество`. Далее строки в двойных кавычках;
кавычка и обратная косая черта экранируются обратной косой чертой.
Переводы строк и нулевые байты внутри кавычек сохраняются как есть, поэтому
текстовый формат предназначен прежде всего для корректного обмена данными,
а не для обработки каждой физической строки отдельной записью.

```text
Array 3
"alpha"
"two words"
"q\"uote"
```

Для дерева после заголовка идут числа без кавычек:

```text
CompleteTree 5
5
3
8
3
-7
```

## Порядок элементов

Массив и списки — от начала к концу; очередь — от головы к хвосту.
Стек сохраняется **от основания к вершине**, чтобы последовательный push
восстановил LIFO. Дерево сохраняется по уровням слева направо. Для Complete Tree
количества и последовательности значений достаточно, чтобы восстановить форму.
Нельзя использовать эту компактную запись для произвольного разреженного дерева.
Хеш-таблица сохраняет ключи, а не индексы ячеек; порядок ключей не гарантируется.

## Контроль ошибок

Проверяются тип, счётчики, усечённые данные, ошибки чтения и записи. Общий предел
счётчика и длины отдельной строки — 2^24; массив и хеш-таблица дополнительно
ограничены собственной ёмкостью 65536. При ошибке десериализации объект сохраняет
прежнее состояние: новая структура строится во временном объекте.

Методы Go возвращают error, C++ выбрасывают исключения. CLI открывает выходной
файл только после успешной загрузки и проверки хвоста входа. Прямые записи
в выходной файл при последующей ошибке диска не являются транзакцией.
Формат не предназначен для проверки подлинности, не содержит контрольной суммы
и не задаёт межпроцессные блокировки. Он является учебным форматом хранения.
