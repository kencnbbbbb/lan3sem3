# Проверка выполненной работы

Дата: 2 ноября 2026 года, часовой пояс Asia/Novosibirsk.
Среда: macOS arm64; Apple Clang, Go 1.26.2, CMake 4.4.4, Python 3.
Минимальные версии проекта: C++17, CMake 3.20, Go 1.22, Python 3.9.
Старые версии Go и отдельные Linux/Windows окружения не запускались.

## Соответствие требованиям

| Требование | Реализация и доказательство |
|---|---|
| C++ и один из Go/Rust | C++ `str/` и Go `golang/ds/` |
| Многофайловая ООП-модель | Закрытые поля, методы, интерфейсы Serializable/Serializer |
| Все структуры | Массив, оба списка, очередь, стек, оба режима хеширования, Complete Tree |
| Дерево согласно ЛР1 | Complete Binary Tree, исходный вариант дерева 3 |

| Три C++-фреймворка | Реальные Google Test, Boost.Test и Catch2, отдельные запуски |
| Go testing и testify | Модульные тесты в ds, pinned testify и vendor |
| Benchmark | Google Benchmark и testing.B, три повтора |
| Линтеры | Clang Static Analyzer, cpplint, go vet, gofmt; журнал lint.txt |
| Бинарный и текстовый форматы | В обеих версиях для каждого контейнера |
| UML | Диаграммы в PDF/SVG и исходники Mermaid |
| Теория нечётного варианта | Российские стандарты + основные виды тестирования |
| Ограничение 15 страниц | Весь PDF занимает 9 страниц, теория — его часть |
| Источники | Официальные карточки Росстандарта и ISTQB, ссылки в отчёте |

## Выполненные проверки

- Google Test: 132 теста, все пройдены; XML и журнал в gtest/.
- Boost.Test и Catch2: все сценарии пройдены. Число тестов, инстанцирований шаблонов,
  секций и утверждений разные фреймворки считают по-разному — их не суммировали
  как однородные показатели. Данные содержатся в XML каждого запуска.
- Для каждого C++-фреймворка отдельно собран профиль; покрытие всей библиотеки
  — 1087/1090 строк для Google Test и 1084/1090 для каждого из двух остальных.
- Go: 774/780 операторов; каждый файл с операторами выше 98%. Проверен не только
  общий процент, но и порог для каждого производственного файла.
- Случайные последовательности хеш-операций для обоих методов сверены со стандартным
  эталонным множеством; проверены повторы, расширение, метки и повторная вставка.
- Сериализация: пустые и заполненные структуры, кавычки, UTF-8, пустые строки,
  переводы строк и NUL; усечение в каждой позиции; ошибки записи; сохранение старого объекта.
- C++ <-> Go: 1354 запуска процессов, оба направления, оба формата, все 8 типов/режимов.
- Go race detector: пройден; это не делает несинхронизированные контейнеры потокобезопасными.
- C++ UndefinedBehaviorSanitizer: 132 теста пройдены, сообщений о неопределённом поведении нет.
- Clang Static Analyzer и выбранные правила cpplint: замечаний нет; Go vet/gofmt также пройдены.
- PDF: визуально проверены все 9 страниц; текст и UML не обрезаны.

## Что именно измерено

Покрытие относится к `str/` и `golang/ds/` целиком, с обработкой ошибок.
Из измерения исключены тесты, внешние библиотеки, benchmark-тесты и CLI для демонстрации.
Такой же подход к фильтрации библиотеки используется в присланном примере.
CLI отдельно проверен реальными межъязыковыми запусками. Процент строк C++
и процент операторов Go не являются одной и той же метрикой.

cpplint запускается по правилам explicit-конструкторов, виртуальных деструкторов,
массивов переменного размера, приведения типов, NULL и альтернативных токенов.
Полную проверку форматирования чужого стиля cpplint не заявляем; дополнительно весь
рабочий C++ проверяется анализатором Clang и строгими предупреждениями компилятора.

## Benchmark и ограничения

Измерения выполнены на одной машине с тремя повторами, ограниченным временем
серии. C++-ADT и драйвер benchmark собраны отдельно с O2 без инструментации покрытия;
сам Google Benchmark собран Release. Время — за серию из N операций/элементов,
не за отдельный insert. Для Go дополнительно сохранены B/op и allocs/op.
Результаты не являются сравнением эффективности языков: различаются строки,
аллокаторы и среда выполнения. Исходные замеры содержатся в JSON/TXT.

AddressSanitizer на этой macOS-машине не завершил инициализацию и был остановлен;
его запуск не засчитывался как успешная проверка памяти. Доступная дополнительная
проверка — завершившийся UndefinedBehaviorSanitizer. Отсутствие всех возможных утечек
или дефектов по этим результатам не утверждается.

Старые личные ЛР1 и ЛР2 не изменены. Внутренние структуры переработаны для инкапсуляции,
а не просто скопированы с публичными полями. Самостоятельная сборка C++ на новом
компьютере требует скачивания закреплённых тестовых зависимостей CMake.
