## Личная ЛР1

Предоставленная папка «лаба 1 семак 3»: процедурные C++-модули `str/` и Go-пакет
`golang/str/`. Закреплённое дерево — Complete Binary Tree, вариант 3.

| До | В объектной версии ЛР3 |
|---|---|
| Array_push_back / Array.PushBack | Array::push_back / Array.PushBack, закрытое хранилище |
| Linked_push_* / LinkedList.Push* | Linked, закрытые узлы и ссылки |
| OneLinked_push_* / OneLinkedList.Push* | OneLinked, закрытые узлы и ссылки |
| Stack_push_back, Stack_pop | Stack::push/pop, проверка пустоты |
| Queue_push_back, Queue_pop | Queue::push/pop, голова и хвост |
| Tree_insert / Tree.Insert | Tree::insert / Tree.Insert, BFS слева направо |
| Tree_find / Tree.Find | Tree::is_member / Tree.IsMember, BFS |
| Tree_is_complete / Tree.IsComplete | Tree::is_complete / Tree.IsComplete, правило первого пропуска |

Семантика дерева и повторов совпадает с личной ЛР1; AVL-вставки, вращения,
BST-поиск и BST-удаление чужого примера заменены. Публичных ссылок на узлы нет.
Отказ от публичных структур и переход к исключениям/ошибкам для неверных
операций — часть переработки в контексте ООП.

## Личная ЛР2

Использована ранее подготовленная и согласованная папка `laba2_variant5`:
`str/open_hash.go`, `str/set.go`, `str/lru.go` и тесты.
Сохранены DJB2/FNV-1a, степень двойки для размера, нечётный шаг двойного хеширования,
линейный шаг 1, метки удаления и перестроение таблицы.
В ЛР3 показана хеш-таблица как множество строк, в соответствии с интерфейсом
класса OpenHash примера. Пары ключ–значение и LRU не входят в перечень обязательных
структур ЛР3 и не выдаются как отдельные классы.

## Дополнительно реализовано

- Serializable: полиморфный интерфейс C++ с виртуальным деструктором.
- Перенос личного Complete Binary Tree в закрытые классы/структуры обеих версий.
- Режим линейного пробирования и тесты обоих методов.
- Portable little-endian вместо зависимости C++ от порядка байтов процессора.
- Проверки ошибок записи, строгий текстовый формат строк, совместимость C++/Go.
- Тесты частичных файлов, частичной записи, сохранения исходного состояния при ошибке.
- Демонстрационные CLI, CMake с закреплёнными зависимостями, проверка покрытия >=85%.
- HTML-отчёты, UML, benchmark-замеры и теория нечётного варианта.

Исходные папки ЛР1/ЛР2 не изменялись. ЛР2 остаётся доступна отдельной папкой.
